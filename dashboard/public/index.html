Weight-space programming, part 3

Agents searching for model grafts on an equal budget

Loading the data snapshot.

A program in this language takes a small host model, Llama-3.2-1B-Instruct with 16 layers, and grafts parts from other donor models into it: a cluster of MLP neurons, a few attention heads, a mixture-of-experts expert or a whole block. Each graft sits at one host layer (its at) and joins the host through a trained glue of some rank, and an optional heal pass trains the glue on task data. The environment compiles each program, scores it on a GSM8K search split and charges two budgets: eval tokens, counted in full-eval equivalents (FEE), and GPU-seconds. An agent swarm (an analyst that maps which parts help, planners that propose programs, and a rule judge that keeps the best) races baselines that get exactly the same two budgets: evolutionary search, random search, a random-part search, greedy union, LoRA and full fine-tuning. The best few programs of each run are then scored once on a held-out split, next to a random-part control and a no-graft control, so a gain that comes from heal training alone shows up as a control that scores just as well.

The race: best score so far

Each thin line is one seed, the thick line is the median over seeds and the shaded band runs from the worst seed to the best. Only full-fidelity search evals that ended "ok" count toward the best. A combined score of 0 is the host's own score; 1 would close all of the host's headroom on GSM8K.

Fit vs score

One point per graft in every scored full-fidelity search eval: its fit_r2 (how well the glue maps the host's activations into the part before any heal) against the eval's combined score.

Budget

What each arm spent of its search budget, as the median over seeds with the range in brackets. Probes are fit-only compiles: they cost GPU-seconds and no eval token.
